# 微信表情开放平台上架规格参考

本文件服务于“微信表情开放平台上架”，不适用于只在聊天中自用的图片。

## 先说结论

- 本次公开资料核对日期：2026-08-17。
- 当前上传页面、提交类型和页面提示是最终依据。
- 公开资料存在版本差异：较早的规范资料写主图为 16/24 张、横幅/封面较小的体积上限；较新的第三方校验器写 8/16/24 张，并放宽了部分延展物料体积。不要把任一第三方页面当作永久官方标准。
- 若无法打开平台上传页，以下只能作为“保守制作基准”，交付时必须标记“待平台复核”。

## 常见物料基准

| 物料 | 常见尺寸 | 常见格式 | 保守制作目标 | 上架前动作 |
|---|---:|---|---:|---|
| 表情主图 | 240×240 | PNG 或 GIF | 单张不超过 500KB | 确认专辑数量为当前页面允许值；全套统一静态或动态 |
| 表情缩略图 | 120×120 | PNG | 单张不超过 50KB | 与主图一一对应；从主图选清晰关键帧 |
| 单品缩略图 | 240×240 | PNG | 单张不超过 60KB | 仅在提交单品时使用，并以页面提示为准 |
| 详情页横幅 | 750×400 | PNG 或 JPEG | 优先压到 80KB 内 | 不放文字；确认当前体积上限 |
| 表情封面图 | 240×240 | PNG | 优先压到 80KB 内 | 透明背景；不加方框；确认当前体积上限 |
| 聊天面板图标 | 50×50 | PNG | 优先压到 30KB 内 | 透明背景；主体足够大；确认当前体积上限 |
| 赞赏引导图 | 750×560 | PNG 或 GIF | 优先压到 100KB 内 | 确认是否启用赞赏以及当前页面是否要求该物料 |
| 赞赏感谢图 | 750×750 | PNG 或 GIF | 优先压到 200KB 内 | 确认感谢图语义、留白和当前体积上限 |
| 创作者头像（如页面要求） | 640×640 | PNG 或 JPEG | 优先压到 500KB 内 | 以当前资料页提示为准 |

“保守制作目标”是为了减少上传失败，不是对当前官方上限的承诺；如果平台页面给出更严格限制，按更严格限制；如果给出更宽松限制，可以在不损害清晰度的前提下采用页面限制。

## 设计与提交规则

- 主图数量不要自动假定。旧资料常见 16/24，新资料常见 8/16/24；生成前让用户确认套数，提交前以当前上传页可选项为准。
- 主图和缩略图必须一一对应，文件名使用稳定序号，例如 `01.png`、`02.png`；不要用关键词中的标点、空格或随机生成名作为唯一索引。
- 动态主图全套统一动态，静态主图全套统一静态；动态内容设置永久循环。若用户只要静态图，不擅自生成 GIF。
- 封面图和聊天面板图标优先透明背景、无白底、无方形边框、少留白、主体清晰；封面更适合正面半身或全身形象，图标更适合辨识度最高的头部正面。
- 详情页横幅使用明快、与微信白底有区分的画面，避免文字，让角色关系和故事在小尺寸预览中仍可识别。
- 文字必须是原创或有授权的字体与素材；表情文案先做版权、敏感内容、可读性和平台审核风险检查。不要把“无文字版本”误当成“可以不做语义表达”。
- 表情名称、介绍、版权信息、一句话简介和含义词的长度限制可能随表单版本变化；提交前直接按当前表单校验，不把旧教程中的字数当成硬规则。

## 上架前最小检查

1. 在平台上传页确认提交类型、专辑数量、静态/动态模式和必填物料。
2. 逐项记录页面提示：尺寸、格式、体积、透明背景、命名、数量和文案字段。
3. 生成上传稿：主图、缩略图、封面、图标、横幅、赞赏图分别放入对应目录，绝不只交一张大图让平台或用户自行裁切。
4. 做一次真实上传前校验；失败时保存错误信息，针对一个失败项修改，不同时改动角色、构图和压缩参数。
5. 在 `manifest.md` 写入 `checked_at`、`platform_entry`、`submission_type`、`asset_count` 和每类物料的实际值。
