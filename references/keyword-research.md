# 微信表情包关键词研究与提取

本参考文件只解决“关键词从哪里来、如何提取、如何判断能不能做成表情”。关键词不能靠模型凭空联想，也不能只把一个主题或行业场景词扩写成一句文案。

## 核心判断

- 默认从当前圈内正在传播的表情、图片梗或固定口头禅中找关键词；先找原梗，再做 IP 化，不先按交易流程脑补一批场景。
- “当前很火”必须由新鲜检索证据支持，不能用模型记忆、旧教程或个人印象代替；证据不足时标记为未知，不包装成热门结论。
- 一个合格候选必须同时有：原文关键词、可追溯的原梗来源、对应的原始图片/视频截图，以及能被角色动作复刻的视觉锚点。
- 关键词文本和原梗画面是两份信息：文本负责保留传播语义，原图负责提供表情、姿态、景别、构图和关键道具。
- 没有原图、只有一句抽象词，或只能靠把字放大来表达的候选，先标记为待验证，不直接生成。

## 研究流程

### 1. 明确范围与数量

先确认 IP 主题、目标数量、使用场景和是否允许淘汰候选。目标数量是上限约束，不是凑数任务；宁可少做，也不要用弱关键词填满套数。

维护“候选数 → 用户确认数 → 已生成数 → 已验收数”的对账表。批量结束前逐项核对关键词和文件，缺一张就标记为未完成，不用“总数看起来差不多”代替核对。

### 2. 找当前原梗

用关键词主题加“表情包、原图、出处、名场面、反应图”等组合搜索当前社区内容。优先保留能看到原图和传播语境的结果，并记录平台、链接、发布日期或检索日期。只听说过但找不到原图的词，不算完成研究。

### 3. 提取原文与视觉锚点

每个候选建立一条记录：

| 字段 | 要记录的内容 |
|---|---|
| 关键词原文 | 从原梗直接抄录，保留口语、语气词、标点和关键措辞；不擅自改写成更“合理”的句子 |
| 来源证据 | 平台、原图/视频链接、检索日期；必要时保存截图或本地参考图 |
| 传播语义 | 这句话在原社区里具体表达什么反应，不只写字面意思 |
| 视觉锚点 | 最能让人认出原梗的动作、脸部局部、姿态、景别、构图或道具 |
| IP 转译 | 哪个 IP 出场、是否需要两人、保留什么、替换什么 |
| 风险与缺口 | 版权/品牌/真人污染、危险动作、文字不可读或来源不稳等问题 |

### 4. 做可视化筛选

逐个问：不读文字时，动作和表情能否让人猜到关键词？原图最关键的识别点能否由 IP 安全复刻？如果答案是否定的，就淘汰、换原图或降级为待验证，不让模型自由解释。

尤其注意：原梗依靠嘴部、眼神、手势或局部特写成立时，要保留原来的视觉焦点和景别，不要为了塞入两个 IP 或更多道具而把关键表情缩没。

### 5. 去重、分组与确认

- 合并只是换字或同一情绪的重复候选，保留视觉识别度更高、传播语义更清楚的一条。
- 按情绪和使用场景分组，例如崩溃、反讽、庆祝、安慰、尴尬；检查整套是否被一种情绪或一种构图占满。
- 将“关键词原文 + 原梗图 + 一句话视觉说明”交给用户确认；用户确认前不批量生图。
- 用户删掉某个候选时，记录删除原因；例如“忍住不笑”如果没有足够稳定的视觉表达，就不为了凑数量保留。
- 用户已经确认过的关键词、文案和角色分配，后续直接沿用，不重复索取同一决定；只有会改变画面结果的缺口才再次询问。

## 生成前的最小记录

每张表情至少带着这些信息进入提示词或 manifest：

```text
Keyword (verbatim): <原梗原文>
Source: <平台 / 链接 / 检索日期>
Meme reference role: emotion / pose / composition reference only
Visual anchor: <动作、局部特写、景别、道具或构图>
IP translation: <单人或双人，以及各自动作>
Do not invent: <不能替换或遗漏的识别点>
User confirmed: yes / no
```

原梗参考图只能借鉴情绪、动作、景别和构图，不复制真人、猴子、品牌、logo、水印、原图文字或背景；身份仍以用户 IP 参考图和已验收三视图为准。
